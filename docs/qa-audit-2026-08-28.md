## 1. Fix first

Ranked by user-visible damage. Each entry names the file, the failure, and how it was verified.

### F-01 · CRITICAL · Alerts — Price alerts re-fire every cycle; one Friday move floods Discord all weekend

The dedupe key is `snap:{ticker}:{captured_utc}` (`services/alerts.py:98`), but every scrape stamps a fresh `captured_utc` even when the data is identical, and both the snapshot and the evaluator run hourly seven days a week. A Friday close of +4.5% against a ≥3% rule fires a new Discord ping roughly every hour across the weekend (~40 duplicates), and re-fires every 10–15 minutes intraday while the daily change stays over threshold. `0009_alerts.sql`'s own comment promises a "coarse time bucket" in the key that was never implemented.

> **Verified:** scripted run — an identical `change_pct=4.5` row re-inserted one second later fired a second event. The repo test only pins "no re-fire without a new snapshot".

### F-02 · CRITICAL · Analyst notes — Weekly notes exclude their own week's news

The 30-day news window ends at the covered week's *Monday* (`analyst_notes.py:490`), but the job runs Saturday evening — so news published Tuesday through Saturday of the covered week never reaches the model, and the no-change fingerprint is built from the same window, so a big mid-week story neither appears in the note nor forces a regeneration until the following week. Corporate actions use a different (unbounded) window, so the two inputs are inconsistent with each other.

> **Verified:** scripted run — a relevance-9 SNTS item published Thursday yields `news: 0` in the context gathered for that Saturday's run. Repo tests only feed news dated before Monday.

### F-03 · CRITICAL · Fundamentals — Filings fetcher reads only page 0; most of each issuer's history is never ingested

brvm.org issuer pages are paginated, but `fetch_issuer_filings` (`brvm_org_filings.py:295`) does a single GET with no page walk — while the issuers *index* fetcher does paginate. The committed Sonatel fixture carries a pager with 6 pages and only 20 PDF links on page 0: roughly 100 older filings never enter the corpus, never get extracted, and the six-year Financials table can only ever be as deep as the last ~20 uploads.

> **Verified:** fixture grep shows `?page=1`…`page=5` plus a `pager-last` element; the fetcher has no pagination loop and no test covers it.

### F-04 · HIGH · Reconciliation — The Phase 8f close cross-check doesn't actually reconcile anything

Three stacked defects. The BOC row parser's board whitelist (`brvm_org.py:110`) omits `TEL`, silently dropping SNTS, ORAC, and ONTBF — the highest-stakes tickers — even though their PDF rows parse cleanly. The production default never aligns the PDF's date with the local session it compares against (`reconcile.py:89`), and because equity daily bars are only written weekly while the bond job stamps a fresh session daily, the comparison usually lands on a date with no equity closes at all. And `check_boc_close` has zero callers — no job, route, or `just` target ever runs it.

> **Verified:** pypdf text of the fixture contains parseable `TEL SNTS …` and `TEL ORAC …` rows; a generic prefix scan finds exactly one missing board. Grep across `src/`, `Justfile`, `scripts/`: no caller.

### F-05 · HIGH · Alerts — Discord webhook secret leaks into logs; delivery queue can wedge forever

`str(httpx.HTTPError)` embeds the full webhook URL — token included — and is logged on every delivery failure (`alerts.py:421,470`). The worker also stops at the first failure with no 4xx/5xx distinction and no retry cap, so a revoked webhook or a single message over Discord's 2,000-character limit blocks the head of the queue permanently: retried, and the secret re-logged, every five minutes, with everything behind it never delivered.

> **Verified:** reproduced the httpx message shape (URL + token present); queue ordering and retry loop confirmed by code read. Repo tests cover only the transient-failure case.

### F-06 · HIGH · TUI — Duplicate watchlist name crashes the app; Shift+W is a dead key; `r` silently deletes

Creating a watchlist whose name slugifies to an existing one raises an unhandled `IntegrityError` through the input handler and exits the whole app (`views/watchlists.py:141`). The advertised sidebar-cycle binding `shift+w` can never fire from a real keyboard — terminals send the character `"W"`, which Textual doesn't map to `shift+w`; the repo test masks this by calling the action directly. And inside the watchlist view, `r` is bound to *remove member*, shadowing the global `r` = refresh: a habitual refresh press deletes the highlighted ticker with no confirmation.

> **Verified:** all three reproduced headless with Textual's pilot — crash traceback, zero actions on `"W"`, member count 2 → 1 on `r`.

### F-07 · HIGH · Fundamentals — Extraction order clobbers good data, re-bills for it, and blanks tabs across periods

The extraction queue processes newest-published first while `replace_period` fully overwrites — so a poorer later filing NULLs out `eps`, `dividend_per_share`, and cash-flow fields from a richer earlier one (`store/financials.py:91` + `store/filings.py:122`; real Sonatel filing dates trigger it). The period is then flagged "shadowed" and re-billed a full ~30k-token call on every recovery run. Related: the Ownership and Segments tabs read only the latest *annual* period, so a statements-only 2024 filing hides 2023's shareholder and segment data that is still sitting in the DB — the exact symptom PR #13 fixed, shifted across period boundaries.

> **Verified:** cross-period blanking reproduced against a migrated scratch DB; ordering + full-replace confirmed by code read. The preserve-on-empty test keeps the same scalars non-null in both extracts, so nothing pins the regression.

### F-08 · HIGH · Ratios — YoY growth sign is inverted whenever the prior year was a loss

`_yoy` computes `(now − then) / then` with no guard on a negative base (`ratios.py:291`): a loss worsening from −100 to −200 reports **+100% growth**, and a recovery from −100 to +50 reports −150%. These figures render on the Financials tab and are quoted verbatim in the analyst-note prompt. Tests cover only positive priors.

> **Verified:** reproduced by snippet with both sign cases.

### F-09 · HIGH · Bonds — Current yield is nonsense for amortizing bonds; a real fixture row renders 48.80%

`current_yield` hardcodes a 10,000 XOF nominal (`bonds.py:223`), but BRVM bonds are frequently amortizing and quoted at residual value. The real fixture row BIDC.O4 (6.10% 2017-2027, quoted 1,250) renders "Current yield 48.80%" next to a YTM of "—" on the live Yield tab — a solvent supranational shown at distressed-debt yields. The bullet-schedule caveat in the template is attached to YTM only, not to current yield.

> **Verified:** observed on the live page during the probe, then root-caused and reproduced by snippet: `current_yield(6.10, 1250.0) → 48.8`.

## 2. Carried over — flagged at Phase 3b, still present

Found in the earlier review of the Phase-3b tree and re-verified as still present at `b15aaa1`.

### F-10 · HIGH · Web / charter gap — The STALE badge means "market closed", not "source down"

`Overview.is_stale = not market_open` (`services/_view.py:60`). A scraper dead for six hours during trading shows no badge — the one case the charter's "stale-data badges" requirement exists for — while fresh close data is labelled STALE every evening. `Quote.is_stale` is never set true anywhere, and the scheduler computes a staleness flag it then discards.

### F-11 · HIGH · Ingest — Phantom weekend sessions accumulate in `index_levels`

`parse_aaz` stamps `session_date=date.today()` (`sikafinance.py:120`) and the hourly snapshot runs seven days a week — Saturday and Sunday get their own rows carrying Friday's level, so index charts grow flat weekend points (verified live: an Aug-19 fixture level landed as session Aug-28). It also uses server-local date rather than `clock.session_date_for()`, so evening polls from Montreal stamp the wrong Abidjan session date.

### F-12 · MEDIUM · Corporate actions — "A préciser" dividends duplicate once the real ex-date is announced

The upsert key is `(ticker, kind, ex_date)`, so when sikafinance later publishes a date, a second row is inserted and the NULL-dated row lingers forever — the upcoming calendar lists the same dividend twice (reproduced with the SMBC fixture row). About half the live calendar is "A préciser", so this fires routinely.

### F-13 · MEDIUM · Providers — Filling `BRVM_API_*` in .env silently kills all quote ingestion

`select_provider` returns the stub `ApiProvider` — which raises `NotImplementedError` — whenever both vars are set (`providers.py:116`), with no scraper fallback. `env.example` actively invites filling them for a future paid feed; combined with F-10, data then goes stale with no UI signal.

### F-14 · LOW · Config — `USER_TZ` is dead configuration

The charter says timestamps render "in Africa/Abidjan or America/Montreal per user setting"; the setting exists in `config.py` but is referenced nowhere — everything renders Abidjan/UTC.

### F-15 · LOW · Scraping — Company-description fallback fetches the same afx page twice

When sikafinance fails, `afx_kwayisi.fetch_ticker()` is called and its result discarded, then the same page is fetched again raw (`company.py:99`) — confirmed in the live server log as two afx warnings per page view. A politeness-budget waste.

## 3. Alerts · Brief · Analyst notes

### F-16 · MEDIUM · Alerts — A new filing/news rule fires against the entire historical corpus

`evaluate_new_filings` is called with no `since` anchor and rules carry no created-at (`alerts.py:378`): add a wildcard rule after a real filings pull and ~100 events about years-old documents drain to Discord at 10 per 5 minutes — roughly 50 minutes of spam.

### F-17 · MEDIUM · LLM budget — Unknown-model pricing falls back to the cheapest rate, weakening the hard caps

`price_per_mtok` bills any unmatched model at Haiku rates (`llm.py:140`): an Opus-class override would under-record spend ~5×, so a "$3/day" cap really allows ~$15. A budget gate should fall back to the *most expensive* known rate. The `claude-sonnet-5` table entry is also stale ($3/$15 vs actual $2/$10 — over-billing, the safe direction). The models actually configured all bill correctly.

### F-18 · LOW · Brief — The day's last news cycle misses the brief; the brief runs on holidays

News polled at 15:23 is tagged at 15:31, but the brief gathers at 15:30 and requires a relevance stamp — end-of-session news is invisible to that day's brief, contradicting the phase log's claim. The Mon–Fri cron also fires on WAEMU public holidays, producing a "session recap" of the prior session's stale data (no trading-day gate exists).

### F-19 · LOW · Brief — Cap is per-covered-day, not per-real-day

Backfilling N historical briefs in one day gets N fresh caps (`brief.py:330`) — real-day spend is unbounded by `BRIEF_DAILY_CAP_CENTS`. Documented as intended and the scheduled path is safe, but it deviates from the charter's "cap daily API spend" and from analyst notes, which correctly bill real today.

### F-20 · LOW · Alerts — One `last=None` snapshot aborts the whole evaluation cycle

`f"{last:,.0f}"` raises `TypeError` on None (`alerts.py:118`) and `Quote.last` is nullable — a single partially-parsed row kills that cycle's filings and news evaluation too. Caught by the scheduler, but no events fire.

### F-21 · LOW · Web — Alert-rule form 500s on non-numeric input; threshold 0 creates a fire-on-everything rule

`float(threshold_pct)` runs before the try block (`fragments.py:185`) — `abc` returns a 500 instead of a 400 — and there is no floor check, so 0 matches every move. The TUI editor validates properly.

### F-22 · LOW · LLM budget — Billed retry attempts are lost when the second call hits a transport error

If attempt 1 succeeds (billed) with an unusable reply and attempt 2's HTTP call raises, the generic handler assumes "nothing billed" — attempt 1's real cost never lands in the spend table and the item is fully re-billed next pass. Shared by the news tagger (`llm.py`) and the extractor (`extraction.py:467`): an under-count inside a hard-cap system.

## 4. Fundamentals pipeline

### F-23 · MEDIUM · Deployment — Filings store absolute paths; the Mac → VPS move the charter plans for breaks silently

`_filings_root()` absolutizes the default relative root and stores `str(dest)` (`filings.py:245`), despite `0005_filings.sql` documenting paths as project-relative. Move the DB and corpus to the Hetzner box and every pass logs `skipped_missing_file` forever — and the PDFs are never re-downloaded because their URL hashes already exist.

### F-24 · MEDIUM · Financials tab — The annual table labels every year with the newest row's currency

`series.currency = rows[0]["currency"]` (`fundamentals.py:340`) drops per-row currency; a EUR comparative year renders under an "amounts in XOF" caption with no flag, contradicting the Phase 4b notes. The ratios engine, by contrast, handles per-row currency correctly.

### F-25 · LOW · LLM budget — Cash-flow recovery re-bills filings that structurally can't yield cash-flow

A filing whose cash-flow statement sits past the 120k-char truncation (or doesn't exist) re-extracts to NULL, stays in the recovery query, and is re-billed ~30–50k tokens on every `fundamentals-recover-cashflow` run (`fundamentals.py:581`). Needs a tried-and-failed stamp.

### F-26 · LOW · Filings — Persisted-NULL slugs re-run fuzzy matching every poll, against the documented invariant

A known slug with NULL ticker falls through to fuzzy resolution on every poll (`filings.py:213`); the store docstring, the phase log, and a test comment all claim the opposite. Cheap in practice — fix the code or the docs, either way.

### F-27 · LOW · Politeness — Pull pacing is per-issuer, not per-request; and the pull job isn't scheduled at all

An issuer with 20 new PDFs downloads back-to-back with zero delay (the 0.5s sleep sits outside the download loop, `filings.py:405`), failed downloads skip the sleep entirely, and `filings_pull` is absent from the scheduler — the nightly OCR/extract pipeline only chews on manually-pulled corpora.

### F-28 · LOW · Ratios — Surface inconsistencies: negative P/E rendered, gap-year "YoY", unguarded period trust

Negative EPS renders as "−4.10x" P/E while negative P/FCF is deliberately suppressed two blocks down; growth across a gap year (2024 vs 2022) is still labelled "YoY"; and `_persist` trusts the model's `period_kind` over the filing's own metadata with no cross-check — a mislabelled interim could full-replace a genuine annual row.

### F-29 · LOW · Filings — Oversize download aborts leave a `.part` file behind

The mid-stream size-cap return skips cleanup (`filings.py:324`) — reproduced with a mock transport — contradicting Phase 4a's "never keeps a partial". Disk litter only, but a straight contract violation.

## 5. Bonds

### F-30 · MEDIUM · Parsing — `parse_nom` misses real name shapes in the committed fixture

Tranche suffixes (`TPCI 5,95% 2017-2024 - A`) and spaced year ranges (`TPBF 6.50% 2011 - 2016`) fail the regex (`brvm_org_bonds.py:118`) — four fixture rows get NULL coupon/maturity/issuer forever: no schedule, no YTM, no Related-bonds grouping, despite the data being on the page.

### F-31 · LOW · Cash flow tab — Final-year bonds render a bodiless cash-flow table and drop the principal repayment

An empty-but-truthy `BondSchedule` (real fixture row BIDC.O5, maturity 2026) takes the "have schedule" template branch: header-only table, no terminal principal row, instead of the designed "schedule unavailable" message (`bonds.py:124`).

### F-32 · LOW · Cross-links — Issuer-equity cross-link misses every BOA bond; ECOBANK link points at the wrong listing

Brand token `BOA` can never match the equities' `BANK OF AFRICA …` names (`bonds.py:301`); and the pinned `ECOBANK CI` → `ETIT` mapping links a CI subsidiary's bond to the Togo-listed parent (test-pinned as intended — flagged for awareness).

### F-33 · NOTE · Routes — Analyst-archive route gate is inconsistent for bonds

`/s/{ticker}/analyst/{week}` blocks only indices (`pages.py:109`) while the tab route also hides analyst for bonds — a bond note row, if one were ever created, would render through the archive route. Harmless today.

## 6. TUI

### F-34 · MEDIUM · Responsiveness — Synchronous HTTP on the event loop; opening a ticker can freeze the whole TUI

Description, peers, and history fetches run directly in handlers (`views/ticker.py:191,231,339`) with no workers anywhere under `apps/tui/`: cold cache plus a slow source means up to five sequential requests × 15s timeout with clock, input, and rendering frozen. Reproduced with a 2s stub (loop blocked 2.7s). Hard-down sources fail fast, so a fully blocked network degrades fine — it's the *slow* source that hurts.

### F-35 · MEDIUM · Alerts view — Events cursor snaps to row 0 on every 30-second refresh

The cursor clamp runs against a stray second query with `limit=1` (`views/alerts.py:89`), so `min(cursor, 0)` always yields 0 — breaking the "cursor survives repaint" invariant the phase log promises, and running a redundant duplicate query each refresh. Reproduced headless (cursor 3 → 0). Related key-shadowing quirks: `t`/`delete` act on the rules table even when focus is in the events table.

### F-36 · LOW · News ticker — Footer headlines survive at most one second, and the "24h" lookback is fictional

The 1-second chrome repaint re-renders the pool one index ahead of what the rotation just displayed (`app.py:126` + `news_ticker.py:42`) — each headline gets ≤1s of screen time, reproduced headless. Separately, `LOOKBACK_HOURS = 24` is used only in the empty-state copy; the query has no date clause, so weeks-old headlines rotate as if current.

### F-37 · LOW · Chrome — A per-second DB scan, and `o` on Home ignores cursor location

`_paint_chrome` runs a `MAX(captured_utc)` scan every second, forever, even off-hours (`app.py:131`); `o` on the Home view always opens the highlighted *news* row even when the cursor sits in Gainers/Losers; a stale comment claims the paused ticker keeps the last headline (it shows a pause message — the code matches the phase log, not the comment).

## 7. Web & cross-cutting

### F-38 · LOW · Watchlists — Bonds in watchlists render permanent em-dashes

The quote board joins `quote_snapshots` only; bond prices live in `daily_bars`/`bond_snapshots`. Adding a bond works and degrades gracefully — but its row can never show data, even when a price exists (verified live with BIDC.O4).

### F-39 · LOW · Rendering — Markdown `linkify` option is dead; URLs in briefs and notes render as plain text

markdown-it-py requires `.enable("linkify")` in addition to the option (`pages.py:148`); verified empirically — the option alone does nothing.

### F-40 · NOTE · Migrations — Idempotency rests entirely on the tracking table

`migrate.py`'s docstring claims every file carries `IF NOT EXISTS` guards, but the `ALTER TABLE` migrations (0004 onward) are only guarded by `_schema_migrations` — any half-applied state or out-of-band schema execution becomes unrecoverable (hit once during this audit with a hand-seeded DB).

## 9. What held up

Checked deliberately and found solid — the parts of the system worth trusting as-is.

- **Degradation under total network failure.** With every outbound request blocked, web and TUI rendered every page and view without a single traceback — failures caught, logged, and cached so sources aren't hammered.
- **XSS.** LLM output renders through markdown-it with `html=False` — `<script>`, event handlers, and `javascript:` links all verified inert; everything else goes through Jinja autoescape.
- **Spend accounting.** Four isolated counters bill correctly after every call including failed and empty replies; cache read/write multipliers correct; micro-dollar precision; caps checked before every batch (the two gaps are F-17 and F-22).
- **Never-reprocess invariants** hold across the tagger, the extractor, and OCR — items are stamped on every outcome so nothing is billed twice for the same content (except the structural cases in F-25).
- **Tab gating and routing:** bond/index/equity tab visibility, kind-aware redirects, 404s, dotted bond tickers in URLs, lowercase tickers — all correct on the live app.
- **French number and date parsing:** nbsp/narrow-nbsp thousands, comma decimals, mixed formats, `dd/mm/yyyy` — fixture-verified across sikafinance, brvm.org, and the BOC PDF; BOC column math internally consistent for all 32 extracted rows.
- **Bond math structure:** YTM bisection guards, dirty-price convention, percent handling, duration/convexity — correct for bullet bonds (the amortizing gap is F-09).
- **Ingest dedupe and non-clobbering upserts:** news url-hash dedupe, bond enrichment COALESCE, watchlist CRUD, search ranking, directory filters, pagination edge cases.
- **Phase 8j's lazy Chart claim is real** — no history fetch until the tab activates, cache invalidation behaves as documented; timers skip rather than pile up, respect market hours, and idle views do no work.
- **589 tests green** at baseline, plus all agent-run area suites.

## 10. Method

Audited at `b15aaa1` (latest `origin/main`, phases 0–8j complete). Four adversarial area reviews ran in parallel — fundamentals pipeline, alerts/brief/notes, bonds + reconciliation, TUI — each reading the phase log as the spec, reproducing every claim with scripted runs or headless drivers before reporting it. Alongside them: a live probe of the web app against a fixture-seeded database (69 equities and indices, 257 bonds, 40 tagged news items, dividends) with outbound HTTP fully blocked, exercising every route, tab, form, and edge case; and a re-verification of all findings from the earlier Phase-3b review against current code.

A recurring **test-hygiene theme** explains why several of these bugs coexist with 589 green tests: the suites pin the *mechanism* but not the *production default* — calling TUI actions directly instead of pressing keys (F-06), always passing explicit dates where production passes none (F-04), and testing only the data-present or positive-sign case (F-07, F-08). Worth keeping in mind for the fixes: each one should land with a test that exercises the path production actually takes.

No repository files were modified during the audit; the working tree was left exactly as found.
